一、 Watch（觀察及紀錄）

1. 當一個商店系統同時包含網頁、資料庫等多個容器時，為什麼只靠單一 docker run 指令會難以管理？

💬 卡住時問AI老師

請參考以下多維度正確選項（點擊可直接帶入輸入框）：

👉 **(A) 【架構與指令繁複切入】** 指令過於冗長且每次需設定大量環境變數與連接埠，當系統有網頁、資料庫、快取等多個服務時，手動啟動極易出錯。

👉 **(B) 【自動化總開關切入】** 就像開店時如果每天都要手動開燈、開鐵捲門、開收銀機，缺乏一個「總開關或自動化排程」，只要漏掉一個步驟整個系統就無法運作。

👉 **(C) 【團隊協作與標準化切入】** 若只靠個人指令筆記，團隊其他人接手時很難重現一模一樣的啟動環境，缺乏像「整棟大樓的建築藍圖與統一規範」。

2. 影片提到 Docker Compose 的好處是什麼？它通常由哪三大區塊（Services、Volumes、Networks）組成？

💬 卡住時問AI老師

請參考以下多維度正確選項（點擊可直接帶入輸入框）：

👉 **(A) 【系統化定義切入】** 用單一 YAML 檔定義並一鍵啟動多容器，三大區塊分別負責服務定義（Services）、資料持久化（Volumes）與網路互連（Networks）。

👉 **(B) 【生活化 SOP 比喻切入】** 就像是餐廳的「標準作業流程（SOP）與菜單總表」，把前場、後場和倉庫的運作全部寫在同一張表上，一鍵就能讓全店同時開工。

👉 **(C) 【宣告式劇本切入】** 相當於將複雜的微服務架構「劇本化」，讓開發者透過宣告式設定（Declarative），讓系統自動去把各個元件組裝起來。

3. 什麼是 Volume（資料卷）？若沒有設定 Volume，當商店容器被刪除或重啟時，裡面的資料會發生什麼事？

💬 卡住時問AI老師

請參考以下多維度正確選項（點擊可直接帶入輸入框）：

👉 **(A) 【技術原理切入】** Volume 是將容器內的資料掛載到主機實體目錄上持久保存，若沒設定則容器刪除時資料會隨著容器生命週期結束而全部消失。

👉 **(B) 【生活化備份比喻切入】** 就像是在辦公室裡把重要檔案只存在「免洗紙筆記本」上，下班丟掉紙就沒了；而 Volume 就像是把檔案存入「公司保險箱」，即使辦公室翻新重裝，資料依然安全。

👉 **(C) 【資料生命週期切入】** 容器本身設計是「用完即丟（Ephemeral）」的執行個體，必須透過 Volume 實現「資料與運算分離」，才能確保商店的庫存與歷史訂單萬無一失。

二、 Summary（總結）

請依影片內容整理：Docker Compose 是如何將指令整合進單一 YAML 檔？Volume 如何保護商店的關鍵資料？

💬 卡住時問AI老師
引導：請從兩個方向思考：1. 自動化編排（用 YAML 設定檔一鍵開機）；2. 資料安全（用 Volume 把資料保存在主機上避免遺失）。
👉 點擊帶入句型範本：「我學到 Docker Compose 像是商店的總指揮劇本，用單一 YAML 檔把網頁和資料庫等服務整合在一起，一鍵就能啟動。同時，透過 Volume 將重要資料掛載到主機上，即使容器刪除重啟，商店的訂單與庫存資料也不會遺失。」

三、 Question（提問）

請針對 docker-compose.yml 語法或 Volume 掛載路徑提出一個想深入確認的問題。

💬 卡住時問AI老師
引導：想想看在編寫 YAML 檔案時，如果縮排打錯了會發生什麼事？或者當 Volume 的路徑對應寫錯時，系統會怎麼報錯？
👉 點擊帶入問句範本：「老師，當我在編寫 docker-compose.yml 時，如果 YAML 檔的縮排格式不小心用了空白鍵或對齊錯誤，執行 docker compose up 時系統會報什麼錯？我們要怎麼檢查？」
