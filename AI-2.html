一、 Watch（觀察及紀錄）

1. 當一個商店系統同時包含網頁、資料庫等多個容器時，為什麼只靠單一 docker run 指令會難以管理？

💬 卡住時問AI老師

請參考以下多角度正確選項（點擊可直接帶入輸入框）：

👉 **(A) 【架構與指令繁複切入】** 指令過於冗長且每次需設定大量環境變數與連接埠，當系統有多個服務時手動啟動極易出錯。

👉 **(B) 【自動化總開關切入】** 就像開店每天需手動開啟多個設備，缺乏「總開關」排程，漏掉一步即無法運作。

👉 **(C) 【團隊協作與標準化切入】** 僅靠個人筆記難以讓團隊重現一致環境，缺乏統一的建築藍圖規範。

2. 影片提到 Docker Compose 的好處是什麼？它通常由哪三大區塊（Services、Volumes、Networks）組成？

💬 卡住時問AI老師

請參考以下多角度正確選項（點擊可直接帶入輸入框）：

👉 **(A) 【系統化定義切入】** 用單一 YAML 檔定義並一鍵啟動多容器，涵蓋服務、資料卷與網路三大核心區塊。

👉 **(B) 【生活化 SOP 比喻切入】** 就像餐廳的「標準作業流程總表」，一鍵就能讓前後場所有元件同時上工。

👉 **(C) 【宣告式劇本切入】** 相當於將複雜微服務架構「劇本化」，讓系統依宣告自動組裝。

3. 什麼是 Volume（資料卷）？若沒有設定 Volume，當商店容器被刪除或重啟時，裡面的資料會發生什麼事？

💬 卡住時問AI老師

請參考以下多角度正確選項（點擊可直接帶入輸入框）：

👉 **(A) 【技術原理切入】** 將容器內資料掛載到主機實體目錄持久保存，若無設定則隨容器刪除而消失。

👉 **(B) 【生活化備份比喻切入】** 就像免洗筆記本與公司保險箱的差別，確保辦公室重裝時關鍵資產安全。

👉 **(C) 【資料生命週期切入】** 容器屬用完即丟實例，必須透過 Volume 實現「資料與運算分離」。
