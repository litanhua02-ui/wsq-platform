一、 Watch（觀察及紀錄）

1. 在 n8n 中，Trigger（觸發器） 與 Node（處理節點） 分別扮演什麼角色？[cite: 7]

💬 卡住時問AI老師

請參考以下多維度正確選項（點擊可直接帶入輸入框）：[cite: 7]

👉 **(A) 【技術架構切入】** Trigger 是整個自動化流程的「發起開關」（例如收到 Webhook 請求就啟動），而 Node 則是負責對資料進行加工、判斷與輸出的「各個工作站」[cite: 7]。

👉 **(B) 【生活化比喻切入】** Trigger 就像是餐廳的「客人按下的服務鈴或外送單據進門」，而 Node 就像是廚房裡的「切菜、烹調、打包各個料理站點」[cite: 7]。

👉 **(C) 【資料流向切入】** Trigger 標誌著 Data Flow（資料流）的起點與事件觸發源，Node 則是串聯起整個 Workflow（工作流程）的連續運算單元[cite: 7]。

2. 什麼是 Webhook？為什麼外部系統（如手機捷徑、LINE 或 Google 表單）需要透過它將資料傳入 n8n？[cite: 7]

💬 卡住時問AI老師

請參考以下多維度正確選項（點擊可直接帶入輸入框）：[cite: 7]

👉 **(A) 【技術通訊切入】** Webhook 是一種 HTTP 網址端點（Endpoint），允許外部系統在發生特定事件時，透過 POST/GET 即時推送 JSON 結構化資料進來[cite: 7]。

👉 **(B) 【生活化比喻切入】** 就像是商店的「專用收件信箱或櫃檯」，不管外面客人從哪裡寄信來，只要投進這個固定地址，店內系統就能即時接收並處理[cite: 7]。

👉 **(C) 【即時互動切入】** 相較於傳統定時去問對方有沒有資料的輪詢（Polling）機制，Webhook 實現了「事件驅動（Event-driven）」的即時資料對接[cite: 7]。

3. 在處理不同金額或類型的訂單時，n8n 的條件判斷節點（如 IF 或 Filter）能發揮什麼功能？[cite: 7]

💬 卡住時問AI老師

請參考以下多維度正確選項（點擊可直接帶入輸入框）：[cite: 7]

👉 **(A) 【邏輯分支切入】** 可以根據資料欄位（如訂單金額是否大於 1000 元）進行 True/False 分流，讓 VIP 訂單走快速通道，一般訂單走標準處理[cite: 7]。

👉 **(B) 【生活化比喻切入】** 就像是超商結帳時的「自動分流閘門」或「免用現金快速通道」，依據條件自動把顧客導向不同的處理櫃檯[cite: 7]。

👉 **(C) 【資料過濾切入】** 能有效剔除不符合規範或無效的垃圾資料，確保後續送到資料庫或通訊軟體的通知都是乾淨正確的[cite: 7]。

二、 Summary（總結）

請依影片內容整理：資料如何從外部透過 Webhook 進入 n8n，經過節點轉換與條件判斷後完成自動化任務？[cite: 7]

💬 卡住時問AI老師
引導：請從三個步驟思考：1. 資料接收（Webhook 推送）；2. 資料處理（Edit Fields 節點）；3. 邏輯分流（IF / Filter 條件判斷）[cite: 7]。
👉 點擊帶入句型範本：「我學到資料透過 Webhook 進入 n8n 後，會成為工作流程的起點。接著透過 Edit Fields 節點進行資料整理，再透過 IF 條件節點進行分流判斷，最後完成自動化推播或處理。」[cite: 7]

三、 Question（提問）

請針對 Webhook 接收資料格式或條件判斷（IF）節點串接提出一個操作上的問題。[cite: 7]

💬 卡住時問AI老師
引導：想想看在設定 Webhook 時，如果外部傳來的 JSON 資料結構有缺漏，或是 IF 條件判斷的數值型態（文字 vs 數字）比對錯誤會發生什麼事？[cite: 7]
👉 點擊帶入問句範本：「老師，當外部系統透過 Webhook 傳送資料到 n8n 時，如果 JSON 欄位名稱打錯或缺少了，IF 條件判斷節點會怎麼處理？我們要怎麼檢查錯誤？」[cite: 7]
